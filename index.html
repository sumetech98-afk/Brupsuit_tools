01 · INTRODUCTION

🕷️ What Is Burp Suite?

Burp Suite is the world's most popular web application security testing platform, developed by PortSwigger. It's an integrated toolkit that acts as an intercepting proxy, letting you capture, inspect, modify, and replay HTTP/S traffic between your browser and any web application.

Since its first release in 2003, Burp Suite has become the industry standard for web pentesting. Almost every professional bug bounty hunter, web pentester, and security researcher uses it daily. It combines a proxy, a scanner, an intruder (fuzzer), a repeater, and dozens of other tools into one unified interface.

If you're serious about web security, Burp Suite is not optional — it's mandatory. Understanding it deeply separates hobbyists from professional bug bounty hunters.

💡 Note: Burp Suite is written in Java, so it runs on Windows, Linux, and macOS. Kali Linux comes with the Community Edition pre-installed.

04 · INSTALLATION

⬇️ Installing Burp Suite

Option 1: Pre-installed on Kali

Burp Suite comes pre-installed on Kali Linux. Just search "Burp" in the application menu, or run from terminal:

burpsuite

Option 2: Download from PortSwigger

Download the installer from portswigger.net/burp/communitydownload.

Option 3: Install via Snap (Ubuntu)

05 · PROXY SETUP

🔌 Proxy Setup

Burp's Proxy is its core feature. It sits between your browser and the target web application, letting you intercept and modify traffic in real time.

Step 1: Configure Burp Proxy Listener

  • Open Burp → Proxy tab → Options → Proxy Listeners
  • Default listener: 127.0.0.1:8080
  • Enable "Running" checkbox
  • (Optional) Bind to all interfaces: 0.0.0.0:8080 for external devices

Step 2: Configure Browser Proxy

Two options:

  1. Burp's built-in browser — Easiest. Click Proxy → Intercept → Open Browser. It comes pre-configured.
  2. Manual browser config — Use FoxyProxy or system proxy settings:
    • HTTP Proxy: 127.0.0.1
    • Port: 8080

Step 3: Install Burp CA Certificate

To intercept HTTPS traffic, you must trust Burp's CA certificate:

  1. With Burp proxy active, browse to http://burp
  2. Click "CA Certificate" to download cacert.der
  3. Import into browser: Settings → Privacy → Certificates → Import
  4. For Firefox, you may need to set security.enterprise_roots.enabled = true
💡 Note: Burp's built-in browser handles certificate installation automatically — it's the easiest option for beginners.
06 · INTERCEPT

🛑 Intercept & HTTP History

Intercept Tab

When "Intercept is on", every request is paused before being sent to the server. You can:

  • Forward — Send request as-is to the server
  • Drop — Discard the request
  • Edit — Modify headers, parameters, cookies
  • Action — Send to Repeater, Intruder, Scanner, etc.

HTTP History Tab

The HTTP History shows every request/response that passed through the proxy. This is your audit trail — search, filter, and analyze traffic here.

🔍

Search Filter

Filter by status code, MIME type, or search within responses.

🎯

Scope

Define in-scope targets — everything else gets filtered out.

📤

Send to Tools

Right-click any request → send to Repeater, Intruder, etc.

🗂️

Organize

Highlight, comment, and annotate interesting requests.

Target Scope

Recommended Scope Setup: ──────────────────────────── Include: *.target.com Include: api.target.com Exclude: *.google.com Exclude: *.facebook.com Exclude: *.cloudflare.com
07 · REPEATER

🔁 Repeater — Manual Request Crafting

Repeater lets you manually modify and resend any request as many times as you want. It's the most-used Burp tool for manual web testing — perfect for testing edge cases, payloads, and logic flaws.

Workflow

  1. From HTTP History, right-click a request → Send to Repeater
  2. Go to the Repeater tab
  3. Modify the request as needed
  4. Click Send (or Ctrl+Space)
  5. Analyze the response on the right pane

Common Uses

💉

SQL Injection Testing

Manually inject payloads and observe responses.

🕸️

XSS Testing

Test reflected and stored XSS in different contexts.

🔓

Access Control

Change user IDs, tokens, or roles to test authorization.

🎯

Parameter Fuzzing

Modify values one at a time to find edge cases.

💡 Pro Tip: Use Repeater with tabs to test multiple scenarios in parallel. Right-click a tab to rename it for clarity.
08 · INTRUDER

🎯 Intruder — Automated Fuzzing

Intruder automates the process of sending many requests with different payloads. It's used for brute-forcing, fuzzing, and enumeration.

Attack Types

TypePurposeExample
SniperOne payload set, one position at a timePassword brute-force
Battering RamSame payload in all positionsSame value in multiple params
PitchforkMultiple payload sets, parallelUser:pass pairs from a list
Cluster BombAll combinationsuser × pass matrix

Intruder Workflow

  1. Send a request to Intruder (Ctrl+I)
  2. Go to Positions tab — clear existing markers
  3. Select the value to fuzz → click Add §
  4. Go to Payloads tab → load your wordlist
  5. (Optional) Add processing rules: hash, encode, prefix/suffix
  6. Click Start Attack
  7. Sort results by Status Code, Length, or Time to spot anomalies

Common Intruder Uses

🔑

Login Brute-Force

Sniper attack on the password field with a wordlist.

📂

Directory Fuzzing

Enumerate hidden files/directories using common wordlists.

🔍

Parameter Enumeration

Discover hidden parameters and their valid values.

💉

SQLi Fuzzing

Test many SQL injection payloads in bulk.

🕸️

XSS Fuzzing

Test different XSS payloads across input fields.

🎟️

Token Brute-Force

Guess predictable session tokens or API keys.

⚠️ Warning: Intruder generates lots of traffic. Never use it against production systems without explicit permission. It can cause DoS and lock accounts.
09 · SCANNER

🔍 Scanner (Pro Only)

The Scanner automatically crawls and audits web applications for vulnerabilities. It's only available in Burp Professional.

Scanner Phases

🕷️

Crawl

Discovers all endpoints, parameters, and forms.

🔬

Audit

Actively tests for vulnerabilities — SQLi, XSS, SSRF, etc.

📊

Report

Generates findings with severity, evidence, and remediation.

Scan Types

  • Passive scan — Analyzes traffic silently, no extra requests
  • Active scan — Sends payloads to actively test for vulns
  • Crawl + Audit — Full scan of an entire site
  • Scan selected insertion point — Scan a single parameter
💡 Alternative: If you're on Community Edition, use Burp's BApp store to install "Burp Scanner" alternatives — or pair Burp with OWASP ZAP for automated scanning.
10 · DECODER & COMPARER

🔤 Decoder & Comparer

Decoder

Decoder transforms data between formats — perfect for working with encoded payloads.

Supported Formats: ──────────────────────────── Base64 → RW5jb2RlZA== URL → %20%41%42%43 HTML → &lt;script&gt; Hex → 48656c6c6f ASCII Hex → \x48\x65\x6c\x6c\x6f Gzip → compressed data Binary → 01001000 01100101

Comparer

Comparer shows the difference between two requests or responses — useful for finding subtle changes after fuzzing.

  • Send two responses to Comparer
  • Choose Words or Bytes comparison
  • Highlighted differences show up immediately

12 · COLLABORATOR

📡 Burp Collaborator

Burp Collaborator is a server that detects out-of-band vulnerabilities — bugs that don't show up in responses but trigger external interactions. Essential for finding blind SSRF, blind XXE, blind RCE, and more.

How It Works

  1. Burp generates a unique Collaborator subdomain
  2. You inject it into a payload — e.g., http://xyz.burpcollaborator.net
  3. If the server makes a request to that subdomain, Burp logs it
  4. The interaction proves the vulnerability exists

Common Uses

🌐

Blind SSRF

Force the server to fetch an external URL.

📄

Blind XXE

Exfiltrate data via external DTD or entity.

💥

Blind RCE

Trigger reverse DNS lookup to confirm command execution.

📧

Email Injection

Detect outbound email to attacker-controlled addresses.

Example Collaborator payload in XXE: ───────────────────────────────────── <!DOCTYPE foo [ <!ENTITY xxe SYSTEM "http://xyz.burpcollaborator.net/xxe"> ]> <data>&xxe;</data>
13 · WORKFLOW

🔄 Typical Burp Testing Workflow

  1. Configure proxy — Set up browser and Burp listener.
  2. Set target scope — Define in-scope hosts.
  3. Browse manually — Map the application, discover endpoints.
  4. Review HTTP History — Identify interesting requests.
  5. Send to Repeater — Manually test parameters and edge cases.
  6. Send to Intruder — Automate fuzzing and brute-force.
  7. Run Scanner (Pro) — Automated crawling and auditing.
  8. Use Collaborator — Test for out-of-band vulnerabilities.
  9. Document findings — Note vulnerabilities with evidence.
  10. Report — Compile findings into a professional report.
💡 Pro Tip: Always test manually in Repeater before automating with Intruder. Manual testing reveals logic flaws that fuzzers miss.
14 · BEST PRACTICES

✅ Burp Suite Best Practices

  1. Scope first — Set in-scope targets to avoid noise.
  2. Organize — Rename tabs, add comments, use highlights.
  3. Use keyboard shortcuts — Ctrl+R Repeater, Ctrl+I Intruder, Ctrl+Space send.
  4. Save project files — Don't lose hours of work (Pro).
  5. Install essential BApps — Logger++, Autorize, Param Miner.
  6. Test manually first — Repeater before Intruder.
  7. Watch for blind vulns — Use Collaborator on all inputs.
  8. Rotate User-Agents — Some apps block repeated requests.
  9. Rate-limit Intruder — Avoid crashing targets.
  10. Document as you go — Write findings immediately.

15 · LEGAL & ETHICS

⚖️ Legal & Ethical Boundaries

⚠️ Critical Warning: Burp Suite is a powerful offensive tool. Attacking systems you don't own or have explicit written permission to test is a serious federal crime. Unauthorized access to a protected computer carries up to 10 years in prison.

Before You Test

  • Get written authorization — Signed scope document.
  • Define in-scope targets — Only test approved hosts.
  • Agree on rate limits — Especially for Intruder attacks.
  • Have a contact — In case something breaks.
  • Document everything — Timestamps, commands, evidence.
